# PeopleOps Data Hackathon — Indus Weave Textiles HR Pipeline

End-to-end HR data engineering pipeline built for the PeopleOps Data Hackathon case study. The synthetic exports cover 1 April–30 September 2026.

## Technology

- Python 3
- Pandas
- SQLite
- SQL (CTEs, aggregations, window functions)
- ReportLab and Pillow for presentation/ERD generation

## Run on a clean machine

From the project root:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python run_pipeline.py
```

The pipeline rebuilds the SQLite database from the raw files, creates staging and attendance tables, builds the warehouse, runs all ten SQL questions, exports CSV results, and writes data-quality results and presentation files. The database file `data/peopleops.sqlite` is intentionally excluded from Git; it is regenerated by `run_pipeline.py`.

## Pipeline stages

1. **Raw ingestion** (`ingestion/load_raw.py`): loads all 12 provided CSV/JSON files into `raw_*` tables as text, adds source metadata and writes `docs/raw_load_audit.csv`.
2. **Cleaning and attendance** (`transform/stage2_clean_and_attendance.py`): deduplicates employee master records, reconstructs employment-history validity, fills missing roster weeks, maps punches, records rejects/duplicates, expands approved leave, and builds one daily attendance row per employed employee/date.
3. **Clock validation** (`quality/verify_clock_correction.py`): compares the tested -60/0/+60 minute candidates using paired shift check-in/check-out deviations. This diagnostic does not modify raw punches.
4. **Warehouse and analytics** (`warehouse/stage4_warehouse_analytics.py`): builds dimensions and fact tables, runs ten SQL business questions, writes result CSVs, checks data quality, and generates the ER diagram and CFO presentation.

## Outputs

- `warehouse/ddl/`: dimension and fact DDL scripts
- `warehouse/erd.png` and `warehouse/erd.mmd`: warehouse relationship diagram
- `analytics/q01_*.sql` through `analytics/q10_*.sql`: analytical SQL
- `analytics/results/`: one CSV result per SQL question
- `quality/dq_results.csv`: automated checks and their status
- `docs/source_audit.csv`, `docs/raw_load_audit.csv`, `docs/staging_reconciliation.csv`, `docs/clock_pairing_diagnostic.csv`: audit evidence
- `presentation/cfo_findings.md`: key findings, evidence queries and recommendations
- `presentation/slides.pdf`: six-slide demo deck

## Important business definitions and caveats

- Raw exports are not edited by hand; fixes are implemented in code. Raw source tables are kept separate from staging and warehouse tables.
- `employees.csv` duplicates are resolved by latest `updated_at`. Employment-history `valid_to` values are reconstructed from the next `effective_from` date; the latest SCD Type 2 version uses `9999-12-31` for as-of joins.
- A missing roster week carries forward the previous shift. Duplicate punches by the same employee within two minutes count as one; unmapped punches are retained in a rejected-record table.
- Leave days require both Manager and HR approval, must not be cancelled, and exclude Sundays and plant holidays.
- Q03 absenteeism is defined as Absent / (Present + Absent + Missing Punch); On Leave, Holiday and Weekly Off are excluded.
- Q07 defines zero attendance as zero days marked Present. This is an exception screen, not proof of employee misconduct.
- Q08 flags positive earnings in a payroll month after the separation month. The source contains a payroll month rather than an exact payment date, so it cannot prove the exact date of payment.
- Current evidence for the `DEV-SITE-01` one-hour clock adjustment is modest. The adjustment is provisional and must not be described as conclusively proven until the roster-boundary check is validated or a mentor confirms it.
- The results are investigation flags, not automatic proof of fraud or overpayment. Review `quality/dq_results.csv` before presenting.
